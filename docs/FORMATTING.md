# 格式化怎么跑

沙箱里没有 Rust 工具链，所以 `cargo fmt` 在 CI 里跑：`.github/workflows/format.yml`
格式化全库并把结果回推到当前分支。实测把 `fmt_diff_lines` 从 107 压到 0
（rustfmt 1.9.0-stable），之后 `scripts/verify.sh` 里的 `run "format check"` 变成阻断项。

## 三条必须记住的事

1. **它不是闸门。** 它会改代码；闸门只判对错。两个职责合在一条流水线里的话，
   红的时候分不出是产品坏了还是它自己改坏的。
2. **回推的提交未经闸门。** 默认令牌推的提交不会再触发工作流（平台防递归规则），
   所以它顶着的是上一个提交的绿对勾。下一次人工推送才会真正验它，
   而本流水线每次都会把这句话印在报告里。
3. **循环终止靠内容，不靠提交信息。** 已经规范的代码再跑一次零改动，零改动就不提交。

## 它踩过的三个坑（三个都静默）

- **全量 `git add` 把它自己的日志提交进了仓库。** 不仅脏：日志每次都变，
  于是「零改动就不提交」那层终止条件直接失效，而每一轮闸门都是绿的。
  三层修法：临时文件写 `$RUNNER_TEMP`、只暂存已跟踪的 `.rs`、暂存区有非 `.rs` 就红。
- **新产物名字没跟上 `.gitignore`。** 其它产物都在那张登记表里，新加的几个不在。
- **把 `runner.temp` 用在 job 级 `env:` 里，整份工作流无法加载、一次也没跑。**
  job 级 env 拿不到 runner 上下文。而「没跑」与「跑了但没东西要改」在 PR 页面上一模一样：
  那条回写评论一直是上一轮的旧值，而我读到的就是它。
  **这个坑目前没有自动断言守**：工作流文件合不合法只有平台知道，
  我能做的只有一条经验：**回写评论里的 run id 要与当前运行对得上**，
  对不上就说明它根本没跑。现在 `fmt-outcomes.txt` 里带了 `run_id`。
