# 已知限制与实测记录

## 目前的限制

- 大文件模式（> 64 MB）是**只读**的：只建行索引 + 按需读窗口，搜索与替换走磁盘流式路径。
  不假装可以内存编辑：假装的代价是用户敲了一下键才发现改不了，而那时候他已经信任它了。
- 大文件模式不回溯跳行高亮状态：从文件中间开始看时，块注释内的代码会染成普通色。
- 大文件模式的跳转面板不画内容缩略（那会每帧扇整个文件），只画刻度、命中与当前行。
- 横向滚动的行宽只量**可见行**，所以滚动条长度会随滚动微跳。正确做法是缓存全文最大宽度，
  但那在百万行上要整文扫一遗。
- 跳转面板小于 2px 时拒绕工作（`JumpMap::new` 返回 None）：一个像素不可能同时是文首和文末。
- `find_before`（向上查找）是从头正扫，超大文件上是 O(n)，不是 O(1)。
- 非 ASCII 大小写折叠不做完整 Unicode case folding（只折叠 ASCII）。
- 内存编辑器里含换行的模式一律返回零个匹配；跳行替换请走文件级流式路径。
- 字体挑选只看 cmap 覆盖，不看字形好不好：一份覆盖中文但字形很丑的字体会被接受。
- 格式化只能在 CI 里跑（沙箱里没有 Rust 工具链）。而 CI 的回推提交**不会触发工作流**，
  所以格式化提交得等下一次人工推送才会被闸门看到。
- 发布只能由 `workflow_run` 拉起，而条件触发不生效时没有任何断言能开口。
  能做的只是保证跑了就留痕迹：详见 docs/RELEASING.md。

## 踩过的坑

- **`item_spacing.y = 0.0` 写在 `show_rows` 闭包内部等于没写。** egui 已经按「行高 + 默认行距」
  算完了几何，预留高度比真正画出来的多 可见行数 × 行距，底部出现一大块黑色留白。
- **编辑区没拿到「剩下的全部高度」也是同一个形状。** 区域高度不显式算出来的话，
  窗口下半会直接是背景色，而它只让带检查红，不会让任何东西报错。
- **行宽取 `available_width()` 等于没有横向滚动。** 内容永远不会比视口宽，
  超长行被裁掉且滚不过去。
- **整图指标看不见局部空白。** 底部一大块黑色留白（占全图约 15%）既不改颜色数
  也不改背景占比，所以它可以一直存在而闸门全绿。修法是 `--band` 区域检查。
- **横带在左右方向上有一模一样的盲区。** 右侧跳转面板整条没画时，每一条横带里仍然
  有大量正文颜色，于是四条横带全绿而面板根本不存在。修法是 `--vband`，
  并用一个「右侧置空」的变异体先证明横带真的看不见它。
- **带检查的边界不能把另一个区域包进来。** 0.90..1.00 把状态栏（底部 26px = 0.9675..1.0）
  包进去了，于是即使编辑区底部空一大块，光靠状态栏的文字就能让这条带变绿。
- **一层纯逻辑写完了、断言全绿、但输出从没上屏。** `jump.rs` 的映射往返一致、
  单调、首末行可达全部验过，而运行时根本没画那个面板 —— PR 里写着四个区域，
  屏幕上只有三个。看起来比没写还像做完了。修法是一条「那层的输出真的被消费了」的断言。
- **一条会改代码的流水线用全量 `git add`，把自己的日志提交进了仓库。**
  那一轮所有闸门全绿（仓库变脔不会让任何东西报错），而真正的后果是循环终止失效：
  日志每次都变，于是「零改动就不提交」那一层永远不成立。
  三层修法：临时文件写到 `$RUNNER_TEMP`、只暂存已跟踪的 `.rs`、
  暂存区里出现非 `.rs` 就立即红。另外仓库根目录现在也是一张登记表。
- **新产物名字没跟上 `.gitignore` 是上一条的共犯。** 其它产物都在忽略名单里，
  而新加的几个不在 —— 就是那张「手写的登记表」沉默失效。
- **把 `runner.temp` 用在 job 级 `env:` 里，整份工作流无法加载、一次也没跑。**
  job 级 env 拿不到 runner 上下文。而「没跑」与「跑了但没东西要改」在页面上一模一样：
  那条回写评论一直是上一轮的旧值，而我读到的就是它。现在报告里带 `run_id`：
  对不上当前运行就说明它根本没跑。
- **格式化回推之后，PR 头变成一个没有任何检查的提交。** 默认令牌推的提交不触发工作流，
  而 PR 页面上那看起来很像「还在跑」。实际上一个带格式化的分支需要**两次人工推送**：
  第一次让 fmt 红并拉起格式化，第二次才能把格式化后的树送进闸门。
- **扫描器把自己的注释当成了代码（第七次）。** 这次方向反了：我在 format.yml 的
  注释里写下「第一版用了全量 git add」，而那条负向断言正在找它 ——
  于是一条**已经修好**的规矩被判成还坏着。修法是 `strip_yaml_comments`。
- **而那条自证本身也靠上了我的散文：** 它要求注释里存在字串 `add -A`，
  而我把那句注释改得更易读之后，一段完全正确的代码把闸门弄红了。
  **靠我自己散文里的字串的守卫，只会在改措词时假红。** 改成手搓夹具。
- **手写的 gitignore 匹配器只根了尾部 `*`。** 而真实存在的模式是 `gate-step-*.log`
  （星号在中间），于是闸门自己的产物被当成「未登记的垃圾」。是那个匹配器的
  双向自证拓到的，不是我看代码看出来的。
- **失败摘要没带上下文，中文断言消息一条也到不了我手里。** `panicked at ...` 的
  **下一行**才是消息，而原来的 grep 模式只能匹到英文关键词：报告只告诉我
  「哪条断言红了」而不是「为什么红了」。修法是 `grep -A 4`。
- **Windows 上的微软雅黑是 `msyh.ttc`，不是 `msyh.ttf`。** 候选表写错后缀的后果是
  文件根本读不到、一个中文字也装不上，整个界面全是豆腐块，而闸门全绿：
  截图只在 Linux runner 上拍，而那台机器自带 Droid fallback。
- **集合字体里第 0 张脸未必覆盖中文。** 读对了文件但不传 face index，屏幕上仍然是豆腐块。
  而 macOS 上又多一层：候选表里第一个 PingFang.ttc **在 runner 上读不到**，
  靠逐条试才落到 Hiragino Sans GB.ttc。拒绝理由必须逐条带回去，否则这一点看不见。
- **「文件存在且 > 4096 字节」对豆腐块毫无意见。** 一份只有拉丁字的字体完全满足它。
  覆盖必须真的查 cmap，而且要有一条对照断言证明旧检查会放过它。
- **在查找框里敲字会同时写进文档**，如果不先问「焦点归谁」。它不报错，
  只是搜完一次之后文件里多了一串垃圾。
- **夹具太短等于没压到那个情形。** sample.rs 只有十四行时，800px 窗口里中下部
  本来就空，中部带判红判得对 —— 错的是夹具。
- **`cargo test` 默认 fail-fast。** 一个测试二进制红之后后面的一个都不跑，
  而「没跑」与「通过了」在输出里一模一样。
- **macOS runner 的 /bin/bash 是 3.2.57（2007 年）。** 变量要先初始化（配 `set -u`），
  且 `$var` 不能紧跟非 ASCII 字符（会被当成变量名的一部分）。两次的症状都是
  「评论已经成功发出去了，job 才红」。
- **`permissions:` 一写就变白名单。** 没给 `actions: read` 导致下载产物静默挂掉。
- **CI 的运行日志没有工具读得到。** 红了之后手里只有一个比特。修法是把原始输出
  贴成评论，每个平台一个 marker，包括**回写脚本自己的错误输出**。
- **egui/eframe 每个小版本都在改 API。** 0.36：入口是 `App::ui(&mut Ui)` 而不是
  `update(&Context)`；`Context::fonts` 给不可变引用，排版要走 `Painter`；
  `Context::style()` / `set_style()` 换成了 `style_of(theme)` / `set_style_of(theme, ..)`。
- **字节串字面量里不能写非 ASCII**（`b"中文"` 编译不过）。
- **按单文件判的「剥完还剩四成」是一台假红工厂。** 改成聚合判并打印实测值。

## 测不出来

- 真实 GPU / 真机体验：CI 里跑的是软件渲染，只能证明「窗口真的画出了内容」。
  macOS/iOS 风格像不像原生、滚动手感、字体观感，都只能人工验收。
- macOS / Windows 上的真实界面：截图与基准只在 Linux 上跑。字体探测能证明
  「这台机器上真的能解析到一份覆盖中日韩字的字体且 face index 传对了」，
  但**证不了屏幕上真的不是豆腐块** —— 那一步要人拍图。
- 输入法的真实行为（候选框位置、转换段下划线、删周围字符）：适配层与状态机有断言，
  但真实输入法只能人工验收。
- **一条条件触发的工作流到底有没有被拉起**：不跑就没有任何断言能开口。
  只能保证跑了就留痕迹，于是「主干绿了但没有那条评论」成为一个人可读的信号。
- 三张用户截图左边缘那几个彩色碎片：**根因未定**。几个像素动不了任何整图指标，
  也动不了带检查，所以它可以一直存在而闸门全绿。不编原因。
- 每月的 CI 额度花费：用量页面只有人打得开。已知的只有计费规则（macOS 十倍、
  Windows 两倍、按 job 向上取整到分钟），具体金额只能是估算区间。

## 阈值实测值

下面都是 CI（ubuntu-latest、软件渲染、共享 CPU）上的实测值。
性能类阈值只用来拓「彻底卡死 / 白屏 / 死循环」，不当性能基准。

| 项 | 实测值 | 现在的阈值 | 它只拓哪一类失败 |
| --- | --- | --- | --- |
| 截图尺寸 | 1280x800 | 必须是 1280x800 的整数倍 | 窗口根本没按请求尺寸创建 |
| 不同颜色数（旧 UI） | 3063 / 3055 | ≥ 1000 | 空窗口 |
| 不同颜色数（四区域 UI） | 2493 / 2024 | ≥ 1000 | 同上 |
| 背景色占比（旧 UI） | 0.9641 / 0.8980 | ≤ 0.995 | 一张纯色图 |
| 背景色占比（四区域 UI） | 0.7907 / 0.7506 | ≤ 0.995 | 同上 |
| 带 0.00..0.05（工具栏） | 306 / 293 | ≥ 8 | 工具栏根本没画 |
| 带 0.40..0.60（正文中部） | 1064 / 1318 | ≥ 8 | 正文没铺满 |
| 带 0.88..0.96（编辑区底部） | 816 / 1152 | ≥ 8 | **底部留白** |
| 带 0.97..1.00（状态栏） | 319 / 365 | ≥ 8 | 状态栏根本没画 |
| 竖带 0.01..0.14（侧栏） | 1236 / 726 | ≥ 8 | 侧栏根本没画 |
| 竖带 0.95..1.00（跳转面板） | 126 / 189 | ≥ 8 | 跳转面板根本没画 |
| 64 MB 建行索引 | 29~77 ms | < 3000 ms | 索引卡死 |
| 64 MB 全文搜索 | 35~41 ms | < 3000 ms | 搜索卡死 |
| 64 MB 流式替换 | 78~623 ms | < 5000 ms | 替换卡死 |
| 跳转映射往返校验次数 | 491 | > 400 | 语料缩水 |
| Windows 字体探测 | msyh.ttc index=0 faces=2 | 必须取到且字形非零 | 豆腐块 |
| macOS 字体探测 | Hiragino Sans GB.ttc index=0 faces=4 | 同上 | 豆腐块 |
| fmt 不规范文件数 | 0 | 必须是 0（阻断） | 格式漂 |

带检查的颜色数下限 8 是**拍的**，只用来拓「这一条带是纯色的」。它已经拓到过
一个真的空区域（5 种颜色），所以不是装饰。**收紧时要以最小的那一条为准**：
现在最小的是跳转面板竖带（126），拿正文带的上千去卡会把它变成假红工厂。

性能阈值故意给到约 40 倍余量（不是三倍）：共享 CPU 的 runner 抖动很大（同一项
实测跳过 5 倍），留三倍会变成一台假红工厂，而假红会让人学会忽略闸门。

## fmt 差异

历史实测：26 → 100 → 107，一路涨而每一轮都是绿的。
2026-09-06 由 `.github/workflows/format.yml` 在 CI 里跑 `cargo fmt --all` 压到 0，
之后 `run "format check"` 变成阻断项（原 OB-1，已履行完毕）。
从此它只能是 0；不规范时报告里会逐个列出文件名。
