# 带期限的义务

「等下次顺手做」是这类项目里最常见的谎。这里的每一条都有期限，完成判据读代码而不是读我的报告，
并且由 `crates/meta/tests/obligations.rs` 守：完成了还挂着也判红，因为一份挂着已完成事项的清单没人会再读。

## OB-1 让 cargo fmt 变成阻断项

- deadline: 2026-09-26（unix 1790380800）
- 为什么现在不阻断：V1 的代码是在没有 Rust 工具链的环境里手写的，首轮一定一大片格式差异。
  把它直接设成阻断会让真正的行为失败淹在几百条缩进差异里。
- 完成判据（读代码，不读报告）：`scripts/verify.sh` 里出现 `run "format check"`。
- 到期只有两个正确反应，都不是把日期往后挑：要么真的做完了（删掉本条），
  要么确认做不到（挑进 docs/PITFALLS.md 的「测不出来」）。
- 属于哪种义务：**一次性**。履行后直接删掉本条就对，因为它的完成判据本身就会变成一条常驻断言（fmt 阻断）。

## 不登记成义务的事（有理由的记录）

- **截图尺寸断言。** `yi-shotcheck --size WxH` 已经实现，但首轮不启用：无窗口管理器的
  虚拟显示服务器上，实际拿到的窗口尺寸需要先看一眼实测值。在等第一轮的实测值，
  不是在等一个日期。
- **macOS 的中文字体。** 系统自带的中文字体都是字体集合（.ttc），而当前只接受 .ttf/.otf。
  修法取决于上游对字体集合的支持，期限不由我定，所以不给它定期限。
